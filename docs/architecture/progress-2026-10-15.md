## Scope and evidence boundary

This checkpoint reconciles the accumulated source changes and documentation
before the owner-authorized Git commit/push. It does not Publish or modify Dify,
restart services, create Discord roles, enroll/delete a project, or run inference.
Earlier runtime observations retain their original dates. Unit tests below use
fixtures/mocks and do not prove live deployment or cross-project isolation.

## Implemented in current source

- Backend derives the AW5 project tenant from fresh Discord membership and the
  registered role, checks the Published selection and document metadata, and
  builds a query-based Registry shortlist (at most 20 documents / 65,536 bytes).
  Registry metadata is sent on each question; an empty document shortlist is
  valid. It is not a 20-file restriction on ALL retrieval.
- Dify's replacement Registry parser validates the envelope and preserves the
  prior output wrapper. It does not authenticate the caller independently.
- Administrator enrollment uses an explicit stable tenant ID and resolves App
  ID from the app key using the digest-only Dify view. Keys are encrypted in
  AW5 PostgreSQL, not written to the bot or collected through Discord messages.
- One-use login links expire after three minutes; exchanged sessions expire
  after fifteen minutes. Current admin membership, Origin and CSRF are checked.
- Registered projects show Discord role names, expandable Role ID/App ID and a
  pointer cursor for expandable details. Failed name lookup preserves ID display;
  role IDs remain the authorization keys.
- Role changes select an unbound safe role or create a zero-permission role.
  A separate journal protects provisioning/replays; only the role binding changes.
  No automatic member assignment or old-role deletion occurs.
- Explicit project removal requires the exact name and current app/role binding.
  AW5 mappings/history and completed journals are removed transactionally;
  pending/needs-attention journals block deletion. Discord and Dify resources
  remain outside deletion scope. Automatic orphan repair is not implemented.
- Bot Docker settings use an explicit Discord/backend environment allowlist,
  individual runtime file mounts and restricted build inputs. Host secrets,
  legacy registries and Dify credentials must remain outside the bot container.

Implementation: `aw5_backend/{onboarding,source_registry,db,service,integrations}.py`,
`aw5_backend/static/`, `aw5_backend/{schema,dify_read_view}.sql`, and the Discord
adapter. The existing terminal registration route still requires explicit App ID.
Role changes are distinct from arbitrary Dify app/key rebinding, which has no
management UI in this checkpoint.
