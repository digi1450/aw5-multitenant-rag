# Evaluation Question Candidates

These are candidate questions for later review. They are not yet a gold dataset, and no answer or metric should be reported until a human has verified the expected evidence.

## Single-document retrieval

1. What environmental indicators must the Nature Footprint application calculate?
2. What user access levels are required by the TOR?
3. What are the main input-validation and import-security controls in the design specification?
4. Which database tables represent organizations, locations, and reporting periods?
5. Which tables implement users, roles, role permissions, and organization membership?

## Cross-document traceability

1. How is the TOR requirement for access control represented in the system design and database schema?
2. Which design sections and tables support file upload and file management?
3. Does the design specification address the TOR's audit and security requirements? Identify the supporting sections.
4. Which requirements led to the assessment and calculation result tables?
5. Are the entities visible in the ER diagram consistent with the dbdiagram text?

## Insufficient-evidence tests

1. Which cloud provider hosts the production system?
2. What is the exact production database password policy configuration?
3. Which LLM is used by the Nature Footprint application?

The expected behavior for unsupported questions is to state that sufficient evidence was not found, rather than infer a plausible answer.

## Isolation tests for the future multi-tenant prototype

Create a second project corpus with deliberately conflicting facts. Verify that retrieval for the Nature Footprint project never returns chunks from the other project and vice versa. The authoritative tenant and project filters must be generated by the backend from authenticated membership, not accepted blindly from the client.
